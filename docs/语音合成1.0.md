# 语音合成1.0

官方文档：<https://www.volcengine.com/docs/6561/1329505>

本文整理语音合成 1.0 WebSocket 双向流式接口。该接口通过 WebSocket 实时输入文本、流式输出音频，适合低延迟交互场景，也支持声音复刻和混音相关链路。

## SDK 实现状态

当前仓库的 `TTSServiceV2.OpenStreamSession` 使用同一个双向 WebSocket 路径：

```text
wss://openspeech.bytedance.com/api/v3/tts/bidirection
```

示例目录：

```text
examples/tts_v2/websocket
```

当前 SDK 高层配置暴露的是通用最小子集：

- `speaker`
- `audio_params.format`
- `audio_params.sample_rate`
- 多文本分片
- 多 session 复用连接
- `CancelSession`

1.0 文档中包含的 `mix_speaker`、`additions`、时间戳、缓存、水印、情绪、方言、字幕等扩展参数尚未完整暴露为高层 API。

## API 列表

| 接口 | 推荐场景 | 功能 |
| --- | --- | --- |
| `wss://openspeech.bytedance.com/api/v3/tts/bidirection` | WebSocket 实时交互，文本流式输入，音频流式输出 | 语音合成、声音复刻、混音 |
| `wss://openspeech.bytedance.com/api/v3/tts/unidirectional/stream` | WebSocket 一次性输入文本，流式输出音频 | 语音合成、声音复刻、混音 |
| `https://openspeech.bytedance.com/api/v3/tts/unidirectional` | HTTP Chunked 一次性输入文本，流式输出音频 | 语音合成、声音复刻、混音 |
| `https://openspeech.bytedance.com/api/v3/tts/unidirectional/sse` | HTTP SSE 一次性输入文本，流式输出音频 | 语音合成、声音复刻、混音 |

本文对应双向流式接口。

## 请求路径

```text
wss://openspeech.bytedance.com/api/v3/tts/bidirection
```

## 鉴权

新版控制台请求头：

| Header | 必选 | 说明 |
| --- | --- | --- |
| `X-Api-Key` | 是 | 新版控制台获取的 API Key |
| `X-Api-Resource-Id` | 是 | 模型和计费资源 ID |
| `X-Api-Connect-Id` | 否 | 连接追踪 ID，建议使用 UUID |

常用资源 ID：

| Resource ID | 说明 |
| --- | --- |
| `seed-tts-2.0` | 豆包语音合成模型 2.0 字符版 |
| `seed-tts-1.0` | 豆包语音合成模型 1.0 字符版 |
| `seed-tts-1.0-concurr` | 豆包语音合成模型 1.0 并发版 |
| `seed-icl-2.0` | 声音复刻 2.0 字符版 |
| `seed-icl-1.0` | 声音复刻 1.0 字符版 |
| `seed-icl-1.0-concurr` | 声音复刻 1.0 并发版 |

旧版控制台请求头：

| Header | 必选 | 说明 |
| --- | --- | --- |
| `X-Api-App-Id` | 是 | 旧版控制台 APP ID |
| `X-Api-Access-Key` | 是 | 旧版控制台 Access Token |
| `X-Api-Resource-Id` | 是 | 模型和计费资源 ID |
| `X-Api-Connect-Id` | 否 | 连接追踪 ID，建议使用 UUID |

握手成功后服务端会返回 `X-Tt-Logid`，建议记录用于排障。

## 二进制协议

WebSocket 使用二进制协议。整数均为大端序。

基础 header 为 4 字节：

| 字节 | 字段 | 说明 |
| --- | --- | --- |
| 0 左 4 bit | Protocol version | 固定 `0b0001` |
| 0 右 4 bit | Header size | 固定 `0b0001`，表示 4 字节 |
| 1 左 4 bit | Message type | 消息类型 |
| 1 右 4 bit | Flags | 当前接口正常帧使用 `0b0100`，表示携带 event |
| 2 左 4 bit | Serialization | JSON 为 `0b0001`，Raw 为 `0b0000` |
| 2 右 4 bit | Compression | 无压缩为 `0b0000`，gzip 为 `0b0001` |
| 3 | Reserved | 固定 `0x00` |

常用消息类型：

| Message type | 含义 |
| --- | --- |
| `0b0001` | Full-client request |
| `0b1001` | Full-server response |
| `0b1011` | Audio-only response |
| `0b1111` | Error information |

## 事件

| Event | 方向 | 含义 |
| --- | --- | --- |
| `1` | 上行 | `StartConnection` |
| `2` | 上行 | `FinishConnection` |
| `50` | 下行 | `ConnectionStarted` |
| `51` | 下行 | `ConnectionFailed` |
| `52` | 下行 | `ConnectionFinished` |
| `100` | 上行 | `StartSession` |
| `101` | 上行 | `CancelSession` |
| `102` | 上行 | `FinishSession` |
| `150` | 下行 | `SessionStarted` |
| `151` | 下行 | `SessionCanceled` |
| `152` | 下行 | `SessionFinished` |
| `153` | 下行 | `SessionFailed` |
| `200` | 上行 | `TaskRequest` |
| `350` | 下行 | `TTSSentenceStart` |
| `351` | 下行 | `TTSSentenceEnd` |
| `352` | 下行 | `TTSResponse` |

推荐流程：

1. 连接 WebSocket。
2. 发送 `StartConnection`。
3. 收到 `ConnectionStarted`。
4. 发送 `StartSession`。
5. 收到 `SessionStarted`。
6. 通过 `TaskRequest` 流式发送文本。
7. 没有文本后立即发送 `FinishSession`。
8. 收到 `SessionFinished` 后，可以复用连接开启新 session，或发送 `FinishConnection`。

同一个 WebSocket 连接支持多个 session，但不支持同时存在多个 session。

## StartSession 参数

TTS 服务参数仅在 `StartSession` 生效；每次发送的文本在 `TaskRequest` 生效。

| 字段 | 必选 | 说明 |
| --- | --- | --- |
| `user.uid` | 否 | 用户标识 |
| `event` | 是 | `StartSession` 使用 `100` |
| `namespace` | 否 | 默认 `BidirectionalTTS` |
| `req_params.text` | 是 | 输入文本，双向流式不支持 SSML |
| `req_params.model` | 否 | 复刻 2.0 可选 `seed-tts-2.0-standard` 或 `seed-tts-2.0-expressive` |
| `req_params.speaker` | 是 | 发音人或音色 ID |
| `req_params.audio_params` | 是 | 音频参数 |
| `req_params.mix_speaker` | 否 | 混音参数，1.0 音色支持 |

音频参数：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `format` | `mp3` | `mp3`、`ogg_opus`、`pcm`；流式场景不建议使用 `wav` |
| `sample_rate` | `24000` | 可选 8000、16000、22050、24000、32000、44100、48000 |
| `bit_rate` | - | MP3 和 OGG 建议主动设置 |
| `speech_rate` | `0` | 范围 `[-50,100]` |
| `loudness_rate` | `0` | 范围 `[-50,100]` |
| `emotion` | - | 部分音色支持 |
| `emotion_scale` | `4` | 范围 1 到 5 |
| `enable_timestamp` | `false` | TTS 1.0 / ICL 1.0 生效 |
| `enable_subtitle` | `false` | TTS 2.0 / ICL 2.0 生效 |

## 扩展参数

`req_params.additions` 是 JSON string，常见字段：

| 字段 | 说明 |
| --- | --- |
| `silence_duration` | 句尾静音时长，0 到 30000 ms |
| `enable_language_detector` | 自动识别语种 |
| `disable_markdown_filter` | 是否关闭 Markdown 解析过滤 |
| `disable_emoji_filter` | 是否不过滤 emoji |
| `mute_cut_threshold` / `mute_cut_remain_ms` | 静音裁剪配置 |
| `explicit_language` | 明确语种 |
| `explicit_dialect` | 明确方言 |
| `unsupported_char_ratio_thresh` | 不支持字符比例阈值 |
| `aigc_watermark` | 音频节奏标识 |
| `aigc_metadata` | 元数据隐式水印 |
| `cache_config` | 缓存配置 |
| `post_process.pitch` | 音调，范围 `[-12,12]` |
| `context_texts` | TTS 2.0 语音指令 |
| `section_id` | TTS 2.0 多轮会话 ID |
| `use_tag_parser` | 声音复刻 2.0 表现力增强版本语音标签解析 |

## 响应

正常响应帧会携带 event 和 payload：

| 字段 | 说明 |
| --- | --- |
| `data` | 返回的二进制音频数据 |
| `event` | 返回事件类型 |
| `res_params.text` | 文本分句结果 |

`SessionFinished` 可能返回：

```json
{
  "status_code": 20000000,
  "message": "ok",
  "usage": {
    "text_words": 4
  }
}
```

`usage` 仅在请求头携带 `X-Control-Require-Usage-Tokens-Return` 时返回。

## 时间戳和字幕

TTS 1.0 / ICL 1.0：

- 合成多个子句时，会多次返回 `TTSSentenceStart` 和 `TTSSentenceEnd`。
- 开启时间戳后，字幕跟随 `TTSSentenceEnd` 返回。
- 字幕基于 TN 后文本打轴。

TTS 2.0 / ICL 2.0：

- 合成多个子句时，仅返回一次 `TTSSentenceStart` 和 `TTSSentenceEnd`。
- 开启字幕后，会多次返回 `TTSSubtitle`。
- 字幕基于原文打轴。
