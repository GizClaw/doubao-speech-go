# 流式语音识别

官方文档：<https://www.volcengine.com/docs/6561/1354869>

本文整理火山引擎大模型流式语音识别 ASR SAUC WebSocket API。官方文档在同一页面内同时列出豆包流式语音识别模型 1.0 和 2.0 的 resource ID；二者使用同一套 SAUC WebSocket 二进制协议，因此本仓库不再按 1.0 / 2.0 拆分文档。

## 示例目录

```text
examples/asr_v2_sauc_ws
```

## 接口模式

官方服务包含三种 WebSocket 模式：

| 模式             | Endpoint                         | 行为                                                 |
| ---------------- | -------------------------------- | ---------------------------------------------------- |
| 双向流式模式     | `/api/v3/sauc/bigmodel`          | 音频包输入后尽快返回识别更新。                       |
| 流式输入模式     | `/api/v3/sauc/bigmodel_nostream` | 音频大于约 15 秒或发送最后一包后返回更高准确率结果。 |
| 双向流式优化模式 | `/api/v3/sauc/bigmodel_async`    | 只有结果变化时才返回新包，是双向流式更推荐的模式。   |

当前 SDK 示例实现的是双向流式模式：

```text
wss://openspeech.bytedance.com/api/v3/sauc/bigmodel
```

`bigmodel_nostream` 和 `bigmodel_async` 目前未暴露为高层 SDK API。

## 鉴权

### 新版控制台 API Key

新版控制台使用 `X-Api-Key`，并携带资源 ID 和连接追踪 ID：

```http
X-Api-Key: <api-key>
X-Api-Resource-Id: <resource-id>
X-Api-Connect-Id: <uuid>
```

SDK 配置：

```go
client := doubaospeech.NewClient(
	doubaospeech.WithAPIKey(apiKey),
	doubaospeech.WithResourceID(doubaospeech.ResourceASRStreamV2),
)
```

### 旧版控制台 Access Key

旧版控制台使用 app ID + access key。官方表格里的 app-id header 为 `X-Api-App-Key`；SDK 为兼容会同时发送 `X-Api-App-Id` 和 `X-Api-App-Key`。

```http
X-Api-App-Id: <app-id>
X-Api-App-Key: <app-id>
X-Api-Access-Key: <access-key>
X-Api-Resource-Id: <resource-id>
X-Api-Connect-Id: <uuid>
```

SDK 配置：

```go
client := doubaospeech.NewClient(
	doubaospeech.WithAppID(appID, accessKey, appID),
	doubaospeech.WithResourceID(doubaospeech.ResourceASRStreamV2),
)
```

WebSocket 握手响应会返回 `X-Tt-Logid`，排查服务端问题时建议记录。

## Resource ID

resource ID 必须已对当前凭据开通：

| 模型                     | 计费方式 | Resource ID                    |
| ------------------------ | -------- | ------------------------------ |
| 豆包流式语音识别模型 1.0 | 小时版   | `volc.bigasr.sauc.duration`    |
| 豆包流式语音识别模型 1.0 | 并发版   | `volc.bigasr.sauc.concurrent`  |
| 豆包流式语音识别模型 2.0 | 小时版   | `volc.seedasr.sauc.duration`   |
| 豆包流式语音识别模型 2.0 | 并发版   | `volc.seedasr.sauc.concurrent` |

SDK 默认值：

```go
doubaospeech.ResourceASRStreamV2 // "volc.seedasr.sauc.duration"
```

可以通过 `WithResourceID(...)` 或示例的 `-resource-id` 参数选择其他已开通资源。不要假设 1.0 和 2.0 的资源授权互通。

## 最小运行命令

```bash
DOUBAO_API_KEY=<your_api_key> \
go run ./examples/asr_v2_sauc_ws
```

Access Key 模式：

```bash
DOUBAO_APP_ID=<your_app_id> \
DOUBAO_ACCESS_KEY=<your_access_key> \
go run ./examples/asr_v2_sauc_ws \
  -audio /path/to/audio.pcm \
  -resource-id volc.seedasr.sauc.duration
```

如果不传 `-audio`，示例会使用 Git LFS 管理的内置音频 `sample_zh_16k.pcm`。克隆后需先执行 `git lfs pull`。

## 音频输入

当前示例只支持 PCM：

- format: `pcm`
- sample rate: `16000`
- channel: mono
- sample width: signed 16-bit PCM

官方分包建议：

- 单包音频约 100-200 ms。
- 发包间隔约 100-200 ms。
- 双向流式模式推荐 200 ms 分包，性能最优。
- 分包过大或过小都会影响性能。

示例默认 `3200` bytes，即 16 kHz mono 16-bit PCM 的 100 ms。

## 请求流程

1. 携带鉴权和资源 header 建立 WebSocket 连接。
2. 发送包含音频元信息和请求参数的 full client request。
3. 持续发送 audio-only frame；最后一包设置 final 标记。
4. 接收中间和最终识别结果。
5. 关闭 session。

## 结果说明

`ResultType` 默认返回全量结果。最终结果之前，服务可能返回多次中间识别更新；需要稳定文本时应以 final 标记为准。

服务支持 ITN、标点、分句、语种提示、VAD、上下文、热词、POI/music function call 等扩展字段。当前 SDK 暴露稳定通用字段，后续可按需扩展更多请求参数。

## 常见错误

- `requested resource not granted`：凭据有效，但所选 `X-Api-Resource-Id` 未开通。
- `Invalid X-Api-Key`：API Key 不被服务接受。
- 缺少凭据：设置 `DOUBAO_API_KEY`，或设置 `DOUBAO_APP_ID` + `DOUBAO_ACCESS_KEY`。
- 音频格式错误：示例输入保持 16 kHz mono PCM。
